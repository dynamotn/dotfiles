# Generate `docs/dytoy.md` from the dytoy YAML definitions

## Intent

Adding a tool to dytoy means writing `home/.chezmoitemplates/dytoy/<tool>.yaml[.tmpl]`
and then, separately, adding a row to `docs/dytoy.md`. The second step is the
one that gets forgotten. The fix is to make the definition file the only place
a tool is described, and to regenerate the doc tables from it on every commit.

Success: adding a tool is one file. A file without its doc block fails the
commit; a file with one updates `docs/dytoy.md` on its own.

## Goals

- Each definition file carries the data its doc row needs.
- A pre-commit hook regenerates the generated part of `docs/dytoy.md` whenever
  a dytoy definition (or the generator) changes. If the doc changed, the hook
  fails with "docs/dytoy.md regenerated, re-stage it", the way
  `end-of-file-fixer` does. A definition with a missing or malformed doc block
  also fails the hook, naming the file.
- The output is identical on every machine (Linux, macOS, Android): it never
  depends on who renders it.

## Non-goals

- Showing which OS or machine a tool is for. Rows stay "name + purpose" as now
  (user's decision).
- Rewriting the intro, `## Usage` and its key table.
- Changing how `dytoy` installs anything.

## Anti-goals

- A slow hook. Target: well under a few seconds; it must not run on commits
  that touch no dytoy file.
- A second hand-maintained list of tools.
- Editing a description re-running an install script on the next
  `chezmoi apply`.

## Data model: a doc block in a template comment (user's decision)

Docs data lives in a Go template comment at the top of the definition file,
outside every `{{ if }}`, so it renders to nothing and the generator reads it
from the raw file text **without rendering**:

```
{{- /* doc
name: lazydocker
label: lazydocker
url: https://github.com/jesseduffield/lazydocker
description: Interactive TUI with Docker and Compose
category: [DevOps tools]
*/ -}}
{{- if ne .chezmoi.os "android" }}
name: lazydocker
...
```

The body between `doc` and `*/` is YAML. Fields:

| Field | Required | Meaning |
|---|---|---|
| `name` | yes | Tool name; must equal a `name:` line in the same file (generator checks). |
| `description` | yes | The "Purpose" cell. Markdown allowed (backticks are used today). |
| `category` | yes | List of section titles the row appears in (usually one; `cht` is in two today). Allowed values: the current section titles, in doc order, plus `Prerequisite`. |
| `label` | no | Link text, default `name`. Needed where they differ: `rg` → `ripgrep`, `otel` → `otel-cli`, `wireshark` → `tshark`, `zen` → `zen-browser`. |
| `url` | no | Link target. Default `https://github.com/<github.repo>` read from the file's `repo:` line when there is exactly one distinct repo; otherwise required (generator errors). |

A file may hold several doc blocks: choice files that define different tools
per branch (`web_browser` = firefox or zen, `email_client`, `terminal_emulator`,
`terminal_multiplexer`, `window_manager`, `ddc`) get one block per tool, all at
the top.

Row format stays the current one: `|[label](url)|description|`. Rows whose
current form is plain backticks (`` |`ssh`|SSH client| ``) keep that form: when
`url` is the literal `none`, the row is written as `` |`label`|description| ``.

Applies to the 47 plain `.yaml` files too: `tools.yaml.tmpl` and
`executable_dytoy.tmpl` already render every file with `includeTemplate`, so the
comment is safe there.

## Places that read the raw file and must learn about the block

- `scripts/test/dytoy_schema.bats`, test "plain dytoy yaml files conform to
  schema": strip the doc block (or render the file) before validating.
- `home/.chezmoitemplates/chezmoiscripts/dytoy_install.sh.tmpl`: the
  `run_onchange` hash is `include . | sha256sum`; hash the text with the doc
  block removed, so a description edit does not re-trigger installs.
- Anything else that `include`s the raw text (builder: grep for it).

## Rows with no definition file

A few current rows have no matching definition (GPU drivers, the
`` `tar`, `unzip`… `` prerequisite row if `compression` does not cover it,
links to tools installed by a group file). My call: they go in
`docs/dytoy.extra.yaml`, a list of the same fields, merged by the generator.

Group definitions without a row today (`fonts`, `gpu`, `compression`, `zram`,
`system_zzz`, …, about 25) get a doc block and appear in the doc. My call:
every definition is documented; no opt-out.

## Output

`docs/dytoy.md` keeps its hand-written top (intro, `## Usage`). From
`## Prerequisite` to the end it is generated between markers:

```markdown
<!-- dytoy:begin (generated by scripts/dytoy_docs.sh, do not edit) -->
## Prerequisite
|Tool|Purpose|
|----|-------|
...
<!-- dytoy:end -->
```

`Prerequisite` becomes a category like the others (my call), so `git`, `yq`,
`chezmoi`, `age` appear once, there. The `<!-- toc -->` list is regenerated
too, keeping its `Usage` entry. Category order is the enum order; rows within
a category keep their current order where possible, new rows appended
alphabetically by label (my call; builder may pick plain alphabetical if
"current order" is awkward to keep, and say so).

## Code layout (repo conventions apply)

- `scripts/lib/dytoy_docs.sh`: functions `dytoy_docs::*`, built on dybatpho,
  documented with `# @file` / `# @description`.
- `scripts/dytoy_docs.sh`: entry point; default writes the file, `--check`
  only reports drift (exit non-zero). Uses `dybatpho::opts`. Parses the doc
  blocks with `yq` (already a prerequisite).
- `scripts/test/dytoy_docs.bats`: default `url`/`label`, `url: none`, multiple
  blocks per file, `name` cross-check, missing-block error, marker
  replacement, idempotence.
- Doc-block schema: `schemas/dytoy-doc.schema.yaml`, checked by the generator
  and by a test in `./scripts/test.sh --dytoy`.
- `.pre-commit-config.yaml`: local hook, `pass_filenames: false`, `files:`
  `^home/\.chezmoitemplates/dytoy/|^docs/dytoy\.(md|extra\.yaml)$|^scripts/(lib/)?dytoy_docs\.sh$|^schemas/dytoy`.
- Checks before done: `dyshellint` on changed scripts, `./scripts/test.sh --all`,
  `./scripts/test.sh --dytoy`, `prek run --all-files`.

## Migration (one-off, not committed)

A throwaway script writes a doc block into every definition from the current
doc, matching by name, then by repo URL; unmatched files are listed for
hand-filling. The regenerated doc is diffed against the old one; allowed
differences: new rows for previously undocumented definitions, rows moved into
`Prerequisite`, and ordering. Every other difference is fixed before commit.

## Left to the builder

- How the hash in `dytoy_install.sh.tmpl` strips the block.
- `--check` messages.
