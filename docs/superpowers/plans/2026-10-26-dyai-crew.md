# dyai crew Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let one command run a task on any installed agent CLI (Claude, Codex,
Gemini, opencode, Copilot) in its own git worktree, have a different provider
review the result, and merge it back safely.

**Architecture:** A new sourced library `scripts/lib/dyai_crew.sh` drives each
agent CLI in headless mode. It never talks to a provider API, so every worker
keeps the skills, MCP servers and policy `dyai install` already gave its CLI.
The orchestrator holds no LLM: decomposition stays with the caller (a human,
or a lead agent calling `dyai run` repeatedly). State is one append-only JSONL
file per repository, guarded by `flock`. Ideas borrowed from Bernstein (read
2026-10-26): worktree per task, a completion file instead of trusting the exit
code, log-tail rate-limit detection with provider fallback, FIFO
`--no-commit --no-ff` merge with abort on conflict, cross-provider review.

**Tech Stack:** bash on dybatpho (`cli` module), git worktrees, `jq`, `yq`,
`flock`, `timeout` (coreutils), bats.

**Spec:** none written. This plan is the design. Its decisions come from the
2026-10-26 conversation (ideas 1, 3, 4, 5 and the Bernstein source review).

## Global Constraints

- No new dependency. Only `jq`, `yq`, `flock`, `timeout`, `git` and dybatpho.
- Library functions are namespaced `dyai_crew::<verb>` and documented with
  `# @description`, `# @arg`, `# @stdout`, `# @exitcode`, like `dyai_hunk.sh`.
- Every changed script passes `dyshellint`. Exceptions carry
  `# dyshellint disable=<CODE> <reason>`.
- Prompts reach the CLI as one argv element, never through `eval` or an
  unquoted expansion.
- Worktrees go in `<main checkout>/.worktrees/crew-<id>` on branch
  `crew/<id>`. Resolve the main checkout with
  `git rev-parse --path-format=absolute --git-common-dir`, so running from
  inside a worktree never nests one.
- Runtime state lives in `<main checkout>/.dyai/crew/`, added to the personal
  ignore with `dyai::git_exclude` + `dyai::exclude_add` (pattern `/.dyai/`).
- Task id: `$(date +%Y%m%d-%H%M%S)-<agent>`.
- Never push, never touch `main`/`master` on merge, never `git branch -D`.
- No `CHANGELOG.md` (repository rule). Commit messages follow Conventional
  Commits with scope `dyai`, and carry no agent attribution trailer.

## Review Focus

1. A prompt holding quotes, newlines, `$(...)` or a leading `-` reaches the
   agent byte for byte and runs nothing in the orchestrator. Test in Task 2.
2. Two `dyai run` started at once both land in `tasks.jsonl` with no torn or
   lost line. Test in Task 2.
3. The agent exits 0 but writes no result file: the task is `failed`, not
   `done`. Test in Task 3.
4. `dyai merge` on a dirty working tree, or on `main`, refuses before
   touching anything. Test in Task 5.
5. `dyai run` started from inside an existing worktree creates the new one
   under the main checkout. Test in Task 3.

### Task 2: Agent commands and the task log

**Files:**
- Create: `scripts/lib/dyai_crew.sh`
- Create: `scripts/test/dyai_crew.bats`

**Interfaces:**
- Produces:
  - `dyai_crew::cmd <agent> <mode> <prompt> <outvar>`. Fills the array named
    `outvar` (nameref) with the command line. `mode` is `rw` or `ro`. Dies on
    an unknown agent.
  - `dyai_crew::state_dir`. Prints `<main checkout>/.dyai/crew`, creates it,
    and adds `/.dyai/` to the personal ignore.
  - `dyai_crew::record <id> <json>`. Merges `json` over the task's last
    state plus `{id, ts}`, and appends the result as one line to
    `tasks.jsonl` under `flock` on `tasks.lock`. Every line therefore holds
    the full state. When the line changes `status` and `hooks.on_status` is
    set, `record` runs the hook after the lock is released, with env
    `DYAI_TASK_ID` and `DYAI_STATUS`. A failing hook is logged with
    `dybatpho::warn` and never fails `record`.
  - `dyai_crew::get <id>`. Prints the last line for `id` as JSON. Exits 1
    when there is none.
  - `dyai_crew::list`. Prints the last line of every id, oldest first,
    as `id<TAB>status<TAB>agent<TAB>summary`. A `running` task whose `pid`
    fails `kill -0` is printed as `lost`. `list` never writes the log.

Command lines pinned (verified with `--help` on 2026-10-26, except `codex`,
which is not installed and must be checked against `codex exec --help` before
merge):

| agent | rw | ro differs by |
|---|---|---|
| claude | `claude -p PROMPT --output-format json --permission-mode acceptEdits --strict-mcp-config --no-session-persistence` | `--permission-mode plan` |
| codex | `codex exec --sandbox workspace-write --json PROMPT` | `--sandbox read-only` |
| gemini | `gemini --prompt PROMPT --output-format json --approval-mode auto_edit` | `--approval-mode default` |
| opencode | `opencode run --format json PROMPT` | env `OPENCODE_PERMISSION='{"edit":"deny","bash":"deny"}'` |
| copilot | `copilot --prompt PROMPT --allow-all-tools --silent` | drop `--allow-all-tools` |

For opencode `ro`, the env assignment is passed as a leading `env VAR=...`
element of the array, so callers run the array as is.

### Task 3: `dyai_crew::run`

**Files:**
- Modify: `scripts/lib/dyai_crew.sh`
- Modify: `scripts/test/dyai_crew.bats`

**Interfaces:**
- Consumes: Task 1 config keys, and `cmd`, `state_dir`, `record` from Task 2.
- Produces: `dyai_crew::run <agent|auto> <prompt>`. Prints the task id.
  Exits 0 when the task is `done`, 1 otherwise. Records the status (one of
  `running`, `done`, `failed`, `partial`, `rate_limited`, `timeout`) with
  `{agent, prompt, branch, worktree, base, pid, summary}`. `base` is the
  commit the worktree was created from. `pid` is the agent process, recorded
  with `running`.

Behaviour:
- Create the worktree from `HEAD` of the current checkout. If
  `hooks.post_create` is set, run it in the worktree with env `DYAI_TASK_ID`
  and `DYAI_WORKTREE`. When the hook fails, record `failed` with summary
  `post_create hook failed` and do not start the agent.
- Append a contract to the prompt: edit files only, then write
  `.dyai-result.json` at the worktree root as
  `{"status":"done|failed|partial","summary":"..."}`. Add `/.dyai-result.json`
  to the personal ignore.
- After the agent exits, the orchestrator commits the work itself with
  `git add -A && git commit -m "crew(<agent>): <summary>"` in the worktree,
  skipping the commit when nothing changed. The `rw` modes (`acceptEdits`,
  `auto_edit`) let an agent edit files but not run shell commands, so the
  agent cannot commit on its own.
- Run the array under `timeout --kill-after=30 <timeout>` with
  cwd = worktree, stdout+stderr to `<state_dir>/<id>.log`.
  `# shortcut: timeout signals the CLI only, so grandchildren may survive; switch to a setsid process group if orphans show up.`
- The status comes from the result file. A missing or invalid file means
  `failed`. Exit code 124 means `timeout`.
- Done needs evidence, not just the agent's claim. A `done` claim with
  `base..crew/<id>` empty is recorded as `failed` with summary
  `claimed done without changes`.
- On a non-zero exit, `grep -Eiq 'rate.?limit|usage limit|quota|\b429\b|resource_exhausted'`
  over `tail -n 50` of the log. A match means `rate_limited` and writes
  `<state_dir>/cooldown/<agent>`, holding the epoch until which the agent is
  skipped.
- `auto` walks `global.crew.fallback`. It skips agents that are not on `PATH`
  or are still cooling down, and moves on only after `rate_limited`. Each
  attempt is its own task id.

  - `@test "run marks failed when exit 0 but no result file"`.

  - `@test "run records the agent pid while running"`: the stub sleeps

  - `@test "run from inside a worktree creates under the main checkout"`.

### Task 4: `dyai_crew::review` and `dyai_crew::fix`

**Files:**
- Modify: `scripts/lib/dyai_crew.sh`
- Modify: `scripts/test/dyai_crew.bats`

**Interfaces:**
- Consumes: `get`, `record`, `cmd` (modes `ro` and `rw`), `_attempt` from
  Task 3, and the `reviewer` config.
- Produces:
  - `dyai_crew::review <id> [agent]`. The reviewer defaults to
    `reviewer[<writer>]`. Writes `<state_dir>/<id>.review.md`, prints its
    path, and records `{review, reviewer, verdict, reviewed_sha}`. `verdict`
    is one of `pass`, `fail`, `unknown`. `reviewed_sha` is
    `git rev-parse crew/<id>` taken before the reviewer starts.
  - `dyai_crew::fix <id>`. Runs the writer agent again, in mode `rw`, in the
    same worktree. The prompt holds the original prompt plus the review
    file. It goes through `_attempt` (result file, evidence check, commit),
    then records `verdict: null` and `reviewed_sha: null`, because the head
    moved. Refuses unless the verdict is `fail`.

Review behaviour: the prompt holds the original prompt, the result summary,
and `git diff <base>..crew/<id>`. It asks for one JSON object on the first
output line,
`{"verdict":"pass|fail","findings":[{"path":"","line":0,"severity":"high|medium|low","problem":""}]}`,
followed by any prose. `verdict` comes from that line with `jq`. When the
line does not parse, or the verdict is anything other than `pass` or `fail`,
the verdict is `unknown`. An unknown verdict never counts as a pass. The
reviewer runs `ro` in the task worktree. It refuses with `dybatpho::die` when
the reviewer equals the writer.

  - `@test "fix reruns the writer and clears the verdict"`: verdict `fail`.

### Task 5: `dyai_crew::merge`

**Files:**
- Modify: `scripts/lib/dyai_crew.sh`
- Modify: `scripts/test/dyai_crew.bats`

**Interfaces:**
- Consumes: `get`, `record`, and the `gate`, `require_review` and `fences`
  config.
- Produces: `dyai_crew::merge <id>`. Exit 0 records `merged`. Exit 1 records
  `conflict`, `gate_failed` or `needs_human`, or refuses without recording,
  and leaves the working tree as it was before.

Order, under `flock` on `<state_dir>/merge.lock`:
1. Refuse unless the task is `done`, the current branch is not `main` or
   `master`, and `git status --porcelain` is empty.
2. When `require_review` is true, refuse unless `verdict` is `pass` and
   `reviewed_sha` equals `git rev-parse crew/<id>`. A missing field counts as
   a refusal.
3. When `git diff --name-only <base>..crew/<id> -- <fences...>` lists any
   path, record `needs_human` with those paths as `summary` and exit 1.
4. `git merge --no-ff --no-commit crew/<id>`. On a conflict, run
   `git merge --abort`, record `conflict`, and exit 1.
5. If a `gate` is set, run it through `bash -c`. On failure, run
   `git merge --abort`, record `gate_failed` with the last 20 lines of the gate
   output as `summary`, and exit 1.
6. Commit with `-m "merge(crew): <id>" -m "<summary>"`.
7. Run `git worktree remove` on the task worktree, then `git branch -d crew/<id>`.
   The lowercase `-d` refuses unmerged work, so nothing is lost.

- [ ] **Step 1: Write the failing tests:**
  - `@test "merge commits a done task and cleans up"`.
  - `@test "merge aborts on conflict and records it"`: the tree is clean
    afterwards.
  - `@test "merge aborts when the gate fails"`: gate `false`.
  - `@test "merge refuses on main"`.
  - `@test "merge refuses a dirty tree"`.
  - `@test "merge refuses without a pass verdict"`: covers `fail`, `unknown`
    and no review at all.
  - `@test "merge refuses when the branch moved after review"`: add a commit
    to `crew/<id>` after `reviewed_sha` was recorded.
  - `@test "merge skips the review check when require_review is false"`.
  - `@test "merge stops at a fenced path"`: the diff touches `secrets/x`.
    Status is `needs_human`, nothing is merged, and the tree is clean.
- [ ] **Step 2: Run.** Expected: FAIL.
- [ ] **Step 3: Implement** `merge`.

## Out of scope (named, not built)

- Exposing `run`, `tasks` and `merge` as tools in the existing `dyai mcp`
  server, so a lead agent can drive a crew. This is the natural next plan.
- `laya_route` choosing the agent per task, and `laya_tournament` best-of-N.
- Best-of-N and race mode (just-every/code), two stance-steered reviewers
  (PAL consensus), YAML task recipes (Goose), and a port per worktree (uzi).
- Container sandboxes (container-use) and ACP as the agent interface.
- Automatic task decomposition, a DAG, file-ownership locking, a retry
  ladder, leases with a TTL, signed approvals, and audit hash chains.
