# dyai crew Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let one command run a task on any installed agent CLI (Claude, Codex,
Gemini, opencode, Copilot) in its own git worktree, have a different provider
review the result, and merge it back safely.

**Architecture:** A new sourced library `scripts/lib/dyai_crew.sh` drives each
agent CLI in headless mode. It never talks to a provider API, so every worker
keeps the skills, MCP servers and policy `dyai install` already gave its CLI.
The orchestrator holds no LLM: decomposition stays with the caller (a human,
or a lead agent calling `dyai run` repeatedly). State is one append-only JSONL
file per repository, guarded by `flock`. Ideas borrowed from Bernstein (read
2026-10-26): worktree per task, a completion file instead of trusting the exit
code, log-tail rate-limit detection with provider fallback, FIFO
`--no-commit --no-ff` merge with abort on conflict, cross-provider review.

**Tech Stack:** bash on dybatpho (`cli` module), git worktrees, `jq`, `yq`,
`flock`, `timeout` (coreutils), bats.

**Spec:** none written. This plan is the design. Its decisions come from the
2026-10-26 conversation (ideas 1, 3, 4, 5 and the Bernstein source review).

## Global Constraints

- No new dependency. Only `jq`, `yq`, `flock`, `timeout`, `git` and dybatpho.
- Library functions are namespaced `dyai_crew::<verb>` and documented with
  `# @description`, `# @arg`, `# @stdout`, `# @exitcode`, like `dyai_hunk.sh`.
- Every changed script passes `dyshellint`. Exceptions carry
  `# dyshellint disable=<CODE> <reason>`.
- Prompts reach the CLI as one argv element, never through `eval` or an
  unquoted expansion.
- Worktrees go in `<main checkout>/.worktrees/crew-<id>` on branch
  `crew/<id>`. Resolve the main checkout with
  `git rev-parse --path-format=absolute --git-common-dir`, so running from
  inside a worktree never nests one.
- Runtime state lives in `<main checkout>/.dyai/crew/`, added to the personal
  ignore with `dyai::git_exclude` + `dyai::exclude_add` (pattern `/.dyai/`).
- Task id: `$(date +%Y%m%d-%H%M%S)-<agent>`.
- Never push, never touch `main`/`master` on merge, never `git branch -D`.
- No `CHANGELOG.md` (repository rule). Commit messages follow Conventional
  Commits with scope `dyai`, and carry no agent attribution trailer.

## Review Focus

1. A prompt holding quotes, newlines, `$(...)` or a leading `-` reaches the
   agent byte for byte and runs nothing in the orchestrator. Test in Task 2.
2. Two `dyai run` started at once both land in `tasks.jsonl` with no torn or
   lost line. Test in Task 2.
3. The agent exits 0 but writes no result file: the task is `failed`, not
   `done`. Test in Task 3.
4. `dyai merge` on a dirty working tree, or on `main`, refuses before
   touching anything. Test in Task 5.
5. `dyai run` started from inside an existing worktree creates the new one
   under the main checkout. Test in Task 3.

**Interfaces:**
- Produces:

### Task 3: `dyai_crew::run`

**Files:**
- Modify: `scripts/lib/dyai_crew.sh`
- Modify: `scripts/test/dyai_crew.bats`

**Interfaces:**
- Consumes: Task 1 config keys, and `cmd`, `state_dir`, `record` from Task 2.
- Produces: `dyai_crew::run <agent|auto> <prompt>`. Prints the task id.
  Exits 0 when the task is `done`, 1 otherwise. Records the status (one of
  `running`, `done`, `failed`, `partial`, `rate_limited`, `timeout`) with
  `{agent, branch, worktree, base, summary}`. `base` is the commit the
  worktree was created from.

Behaviour:
- Create the worktree from `HEAD` of the current checkout.
- Append a contract to the prompt: edit files only, then write
  `.dyai-result.json` at the worktree root as
  `{"status":"done|failed|partial","summary":"..."}`. Add `/.dyai-result.json`
  to the personal ignore.
- After the agent exits, the orchestrator commits the work itself with
  `git add -A && git commit -m "crew(<agent>): <summary>"` in the worktree,
  skipping the commit when nothing changed. The `rw` modes (`acceptEdits`,
  `auto_edit`) let an agent edit files but not run shell commands, so the
  agent cannot commit on its own.
- Run the array under `timeout --kill-after=30 <timeout>` with
  cwd = worktree, stdout+stderr to `<state_dir>/<id>.log`.
  `# shortcut: timeout signals the CLI only, so grandchildren may survive; switch to a setsid process group if orphans show up.`
- The status comes from the result file. A missing or invalid file means
  `failed`. Exit code 124 means `timeout`.
- On a non-zero exit, `grep -Eiq 'rate.?limit|usage limit|quota|\b429\b|resource_exhausted'`
  over `tail -n 50` of the log. A match means `rate_limited` and writes
  `<state_dir>/cooldown/<agent>`, holding the epoch until which the agent is
  skipped.
- `auto` walks `global.crew.fallback`. It skips agents that are not on `PATH`
  or are still cooling down, and moves on only after `rate_limited`. Each
  attempt is its own task id.

- [ ] **Step 1: Write the failing tests.** Stub CLIs on `PATH` the way
  `dyai_hunk.bats` `_stub` does. Each stub writes a result file, or prints
  "rate limit exceeded" and exits 1, as the test needs.
  - `@test "run marks done from the result file"`: status `done`; branch
    `crew/<id>` holds the stub's commit.
  - `@test "run marks failed when exit 0 but no result file"`.
  - `@test "run marks timeout"`: `timeout: 1`, the stub sleeps 5.
  - `@test "auto falls back after a rate limit"`: the claude stub
    rate-limits and the gemini stub succeeds. Two records: claude
    `rate_limited`, gemini `done`. A cooldown file exists for claude.
  - `@test "auto skips an agent in cooldown"`.
  - `@test "run from inside a worktree creates under the main checkout"`.
- [ ] **Step 2: Run** the bats file. Expected: the new tests FAIL.
- [ ] **Step 3: Implement** `run`, plus private helpers `dyai_crew::_attempt`

### Task 5: `dyai_crew::merge`

**Files:**
- Modify: `scripts/lib/dyai_crew.sh`
- Modify: `scripts/test/dyai_crew.bats`

**Interfaces:**
- Consumes: `get`, `record`, and the `gate` config.
- Produces: `dyai_crew::merge <id>`. Exit 0 records `merged`. Exit 1 records
  `conflict` or `gate_failed` and leaves the working tree as it was before.

Order, under `flock` on `<state_dir>/merge.lock`:
1. Refuse unless the task is `done`, the current branch is not `main` or
   `master`, and `git status --porcelain` is empty.
2. `git merge --no-ff --no-commit crew/<id>`. On a conflict, run
   `git merge --abort`, record `conflict`, and exit 1.
3. If a `gate` is set, run it through `bash -c`. On failure, run
   `git merge --abort`, record `gate_failed` with the last 20 lines of the gate
   output as `summary`, and exit 1.
4. Commit with `-m "merge(crew): <id>" -m "<summary>"`.
5. Run `git worktree remove` on the task worktree, then `git branch -d crew/<id>`.
   The lowercase `-d` refuses unmerged work, so nothing is lost.

- [ ] **Step 1: Write the failing tests:**
  - `@test "merge commits a done task and cleans up"`.
  - `@test "merge aborts on conflict and records it"`: the tree is clean
    afterwards.
  - `@test "merge aborts when the gate fails"`: gate `false`.
  - `@test "merge refuses on main"`.
  - `@test "merge refuses a dirty tree"`.
- [ ] **Step 2: Run.** Expected: FAIL.
- [ ] **Step 3: Implement** `merge`.
- [ ] **Step 4: Run** the bats file and `dyshellint`. Expected: PASS.
- [ ] **Step 5: Commit** `feat(dyai): merge a crew task behind a gate`.

## Out of scope (named, not built)

  server, so a lead agent can drive a crew. This is the natural next plan.
- `laya_route` choosing the agent per task, and `laya_tournament` best-of-N.
- Automatic task decomposition, a DAG, file-ownership locking, a retry
  ladder, and audit hash chains.
