# dytoy docs generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Regenerate the tool tables of `docs/dytoy.md` from doc blocks in the dytoy definition files, on every commit that touches them.

**Architecture:** Each definition file starts with one or more `{{- /* doc … */ -}}` comment blocks holding YAML. A bash library extracts the blocks from raw file text (no chezmoi rendering), validates them against `docs/dytoy.categories.yaml`, sorts rows, renders markdown, and replaces the region between markers in `docs/dytoy.md`. A local pre-commit hook runs the entry script.

**Tech Stack:** bash on dybatpho, mikefarah `yq` v4, bats (dybatpho's bundled runner), `ys` for schema checks, prek.

**Spec:** `docs/superpowers/specs/2026-10-26-dytoy-docs-generation-design.md`

## Global Constraints

- Doc block exact delimiters: opening line `{{- /* doc`, closing line `*/ -}}`; body is YAML; zero or more blocks, all before the first non-block line.
- Fields: `name` (req), `description` (req), `category` (req, one string), `subcategory` (req), `label` (opt, default `name`), `url` (opt; default `https://github.com/<repo>` from the file's single distinct `repo:` value; literal `none` renders a plain `` `label` `` cell), `order` (opt int).
- Sort within a category: subcategory index in `docs/dytoy.categories.yaml`, then `order` (missing = after all numbered), then label (case-insensitive).
- Row format: `|[label](url)|description|`, or `` |`label`|description| `` when `url: none`. Table header `|Tool|Purpose|` / `|----|-------|`.
- Markers: `<!-- dytoy:begin (generated by scripts/dytoy_docs.sh, do not edit) -->` and `<!-- dytoy:end -->`. Generated region starts at `## Prerequisite`.
- No rendering through chezmoi anywhere in the generator; output identical on any OS.
- Libraries: `scripts/lib/<area>.sh`, functions `<area>::<verb>`, dybatpho helpers, `# @file/@brief/@description/@arg/@stdout` comments, `dyshellint` clean.
- No `CHANGELOG.md`. Commits: Conventional Commits, subject ≤ 50 chars, no agent trailers.

## Review Focus

- A description containing `|` would break the table: must render as `\|`. (Task 2 test `render escapes pipe`.)
- Two files declaring the same doc `name`: must fail naming both files. (Task 2 test `duplicate name across files dies`.)
- `docs/dytoy.md` missing either marker: must fail with a message naming the marker, never truncate the file. (Task 3 test `missing marker dies and leaves file untouched`.)
- A file whose doc `name` matches no `name:` line in the file (typo): must fail naming the file. (Task 2 test `name without matching definition dies`.)
- A YAML-unsafe description (leading backtick, `: `): must round-trip byte-for-byte. (Task 2 test `description with colon and backticks round-trips`.)

### Task 2: Collect, validate, sort, render rows

**Files:**
- Modify: `scripts/lib/dytoy_docs.sh`
- Modify: `scripts/test/dytoy_docs.bats`

**Interfaces:**
- Consumes: `dytoy_docs::blocks`, `dytoy_docs::strip` (Task 1).
- Produces: `dytoy_docs::collect <dytoy_dir> <extra_yaml> <categories_yaml>` → stdout: JSON array (via `yq -o json`) of `{category, label, url, description}` already sorted by category order then the Global Constraints sort; dies (`dybatpho::die`, naming file and field) on: missing required field, unknown category/subcategory, duplicate `name` (both files named), `name` with no `^name:[ \t]*<name>[ \t]*$` line in the stripped file (not checked for `extra_yaml` entries), no `url` and not exactly one distinct `repo:` value.
- Produces: `dytoy_docs::render <categories_yaml>` reading collect's JSON on stdin → stdout: the generated markdown region (marker lines included): for every category in file order that has rows, `## <category>`, blank, header, rows, blank.
